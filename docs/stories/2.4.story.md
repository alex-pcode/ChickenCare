# Story 2.4: Egg Tracking Analytics & Stats Cards

## Status

Done

## Story

**As a** user,
**I want** to see statistics, trends, and goal progress on my egg tracking page,
**so that** I gain actionable insights from my egg data without navigating away.

## Acceptance Criteria

1. `EggStatsService` computes: total eggs, average daily, this week total, previous week total, this month total, previous month total
2. `EggEntryController@index` passes stats data to the view via the service
3. Stats section on `eggs/index.blade.php` displays 4 `<x-ui.stat-card>` components:
   - Total Eggs (icon: egg)
   - Average Daily (icon: chart)
   - Lay Rate — **placeholder** showing `--` until Epic 3 (Flock & Batch Management) provides laying hen counts
   - Protein Generated — `totalEggs × 0.125 lbs`, rounded
4. Two `<x-ui.comparison-card>` components:
   - 7-Day Comparison (this week vs previous week)
   - Monthly Comparison (this month vs previous month)
5. One `<x-ui.progress-card>` for monthly goal progress:
   - Based on `yearly_egg_goal` column on `users` table (new migration)
   - Monthly target = `yearly_egg_goal / 12`, rounded
   - Shows "Set Your Annual Goal" CTA linking to account settings when goal is 0/null
6. Stats section only renders when at least 1 egg entry exists (no stats above empty state)
7. Stats section placed between the form and the data table
8. All stat queries scoped to authenticated user

## Dev Notes

### Project Context

This is an **addendum to Epic 2** closing the gap between the original app's `EggCounter.tsx` (d:\Koke\Aplikacija) and ChickenCare's current egg tracking page. The original app displayed a full mini-dashboard of stats inline on the egg page — ChickenCare currently only has CRUD.

### Placeholder Strategy

Two features require dependencies from later epics:

| Feature | Dependency | Placeholder |
|---------|-----------|-------------|
| Lay Rate | Epic 3 — `FlockBatch` model with `hensCount`, `broodingCount`, `actualLayingStartDate` | Show `--` with label "available after flock setup" |
| "Set Goal" link | Epic 6, Story 6.3 — Account Settings page | Use `#` href with TODO comment |

When Epic 3 lands, the `EggStatsService` should be updated to:
1. Accept or query `FlockBatch` data
2. Calculate `layingHens` = sum of (hensCount - broodingCount) for batches with `actualLayingStartDate`
3. Calculate `layRate` = round((averageDaily / layingHens) * 100)

### Existing UI Components

All three card components already exist from Story 1.4:
- `<x-ui.stat-card>` — supports `icon`, `total`, `label`, `change`, `changeType`, `variant`
- `<x-ui.comparison-card>` — supports `title`, `before` (value/label), `after` (value/label), `format`
- `<x-ui.progress-card>` — supports `title`, `value`, `max`, `label`, `variant` (including `detailed`)

### Existing Model Scopes

`EggEntry` model already has `forWeek()` and `forMonth()` scopes accepting optional `Carbon` date — use these directly in the service.

### Performance Budget

Stats computation should add no more than 6 DB queries to the page load. All queries start from `$user->eggEntries()` for ownership scoping.

### Code Quality Assessment

Well-executed analytics addition. The `EggStatsService` follows single-responsibility principle — extracted from the controller, accepting a `User` and returning a typed stats array. It reuses existing model scopes (`forWeek`, `forMonth`) rather than duplicating query logic, and stays within the 6-query performance budget. The migration is minimal and safe (nullable column, default null). The `UserFactory::withYearlyGoal()` state method is a good pattern for test ergonomics. Placeholder strategy for Epic 3 (lay rate) and Epic 6 (goal link) dependencies is clearly documented with TODO comments.
