# Story 4.2: Feed Inventory

## Status

Ready for Review

## Story

**As a** premium user,
**I want** to track feed purchases and inventory,
**so that** I can monitor feed costs and avoid running out.

## Acceptance Criteria

1. `FeedInventory` model with `$fillable`, `$casts`, `belongsTo(User)` relationship
2. Migration: `feed_inventory` table with all columns per data model spec (`id`, `user_id`, `name`, `quantity`, `unit`, `purchase_date`, `expiry_date`, `total_cost`, timestamps)
3. `FeedInventoryFactory` with realistic fake data
4. `FeedInventorySeeder` that creates 5-8 feed entries per premium user
5. `FeedInventoryPolicy` with view/update/delete ownership checks
6. `FeedInventoryController` with `index`, `store`, `update`, `destroy` actions using `HandlesHtmx` trait
7. `StoreFeedInventoryRequest` form request with validation rules
8. `feed/index.blade.php` with inline HTMX CRUD + pagination (15 per page)
9. `feed/partials/entry-row.blade.php` — single row partial for HTMX swap
10. `feed/partials/edit-form.blade.php` — inline edit form partial
11. `feed/partials/table.blade.php` — table body + pagination for HTMX page swap
12. Expiry date visibility: highlight expired (past) and near-expiry (within 7 days) rows
13. Quantities validate as non-negative
14. Dual response: HTMX requests get partials, standard requests get full page
15. `<x-ui.empty-state>` shown when no feed entries exist
16. Feature SCSS: `_feed.scss` with BEM naming, added to `app.scss`
17. All queries scoped to authenticated user via `$request->user()->feedInventory()`

## Dev Notes

### Project Context

This is the **second story in Epic 4** (Financial Management — Premium Tier). Story 4.1 (Expense Tracking) establishes the first premium CRUD feature. This story follows the identical HTMX CRUD pattern, with the addition of expiry date visual indicators — a unique UI concern not present in previous stories. The feed inventory model has more nullable fields than prior models, testing the pattern with optional data.

### Dependencies

- **Epic 1 complete** — Auth, policies, HandlesHtmx trait, EnsurePremiumTier middleware, shared Blade components all in place
- **Epic 2 complete** — Egg tracking establishes the CRUD controller pattern this story follows
- **Story 4.1 may run in parallel** — no dependency between expense and feed inventory features

### Pattern Reference: Story 2.2

This story follows the exact same controller/views/HTMX pattern as Story 2.2 (Egg Entry Controller). Key patterns to replicate:
- Controller uses `HandlesHtmx` trait with dual HTMX/standard responses
- `Gate::authorize()` for authorization (not `$this->authorize()` — Laravel 12 adaptation)
- Manual table HTML (not `<x-tables.data-table>`) for HTMX `<tbody>` targeting
- Inline create form at top, data table below, partials for row/edit-form/table
- CSRF handled globally via `hx-headers` on `<body>` in app layout

### Unit Enum Values

`kg`, `lbs` — stored as a DB enum (unlike expense categories which are varchar). This is a stable, two-value set unlikely to change.

### Expiry Date Visual Indicators

The view layer must visually distinguish three states:

| State | Condition | CSS Class | Visual Treatment |
|-------|-----------|-----------|------------------|
| Expired | `expiry_date < today` | `.feed__row--expired` | Red/danger styling |
| Near-expiry | `expiry_date` within 7 days | `.feed__row--near-expiry` | Amber/warning styling |
| Normal | No expiry or > 7 days | (none) | Default row styling |

The model provides `isExpired()` and `isNearExpiry()` boolean accessors. The Blade partial uses these to conditionally apply CSS classes. No Eloquent in Blade — the model methods are attribute accessors on the already-loaded model instance, which is acceptable per Rule #9.

### Validation Rules

| Field | Rules |
|-------|-------|
| `name` | required, string, max:255 |
| `quantity` | required, numeric, min:0 |
| `unit` | required, in:kg,lbs |
| `purchase_date` | nullable, date, before_or_equal:today |
| `expiry_date` | nullable, date, after_or_equal:purchase_date |
| `total_cost` | nullable, numeric, min:0 |

Note: `expiry_date` validates `after_or_equal:purchase_date` only when both are present. Laravel's `after_or_equal` rule handles this — when `purchase_date` is null, the rule is skipped since the reference field is absent.

### Technical Constraints

- **Models are thin (Critical Rule #7):** `$fillable`, `$casts`, relationships, and boolean accessors only
- **Ownership scoping (Critical Rule #1):** `user_id` FK enforces at DB level; policy enforces at app level
- **Policies for authorization (Critical Rule #8):** `Gate::authorize()` in controller
- `user_id` NOT in `$fillable` — feed entries created via `$request->user()->feedInventory()->create()`
- Premium middleware enforces tier — free users blocked before controller logic runs
- `unit` is a DB enum — requires migration change to add new values (acceptable for stable two-value set)

### Refactoring Performed

- **File**: `app/Http/Controllers/FeedInventoryController.php`
  - **Change**: Removed `&& $request->has('page')` from the HTMX guard in `index`.
  - **Why**: Story 4.1's original controller had the same pattern and it caused a broken-DOM bug when HTMX requests didn't include `?page=`. While 4.2 has no filter bar (so the bug doesn't manifest today), the guard is fragile — any future HTMX call to the index without a page param would silently return full-page HTML. The corrected Epic 4 standard (established in the 4.1 review) is `if ($this->isHtmx($request))`.
  - **How**: All HTMX requests to `index` now consistently receive the table partial. Standard browser requests still receive the full view.

- **File**: `resources/views/feed/partials/table.blade.php`
  - **Change**: Wrapped table HTML in `@if($feeds->isEmpty())` / `@else` with an `<x-ui.empty-state>` for the empty case.
  - **Why**: Without this guard, an HTMX pagination request that arrives on a now-empty page (e.g., last item on page 2 was just deleted) renders an empty `<tbody>` with no user feedback. Applied the same fix from the 4.1 review for consistency.
  - **How**: Empty paginator result now shows a "No feed entries found" empty state.
