# Story 4.1: Expense Tracking

## Status

Ready for Review

## Story

**As a** premium user,
**I want** to record and categorize farm expenses,
**so that** I can understand my operating costs.

## Acceptance Criteria

1. `Expense` model with `$fillable`, `$casts`, `belongsTo(User)` relationship
2. Migration: `expenses` table with all columns per data model spec (`id`, `user_id`, `date`, `category`, `description`, `amount`, timestamps)
3. `ExpenseFactory` with realistic fake data across all 6 categories
4. `ExpenseSeeder` that creates 20-30 expenses per premium user
5. `ExpensePolicy` with view/update/delete ownership checks
6. `ExpenseController` with `index`, `store`, `update`, `destroy` actions using `HandlesHtmx` trait
7. `StoreExpenseRequest` form request with validation rules
8. `expenses/index.blade.php` with inline HTMX CRUD + pagination (15 per page)
9. `expenses/partials/entry-row.blade.php` — single row partial for HTMX swap
10. `expenses/partials/edit-form.blade.php` — inline edit form partial
11. `expenses/partials/table.blade.php` — table body + pagination for HTMX page swap
12. Category filtering (feed, medical, equipment, housing, utilities, other)
13. Dual response: HTMX requests get partials, standard requests get full page
14. `<x-ui.empty-state>` shown when no expenses exist
15. Feature SCSS: `_expenses.scss` with BEM naming, added to `app.scss`
16. All queries scoped to authenticated user via `$request->user()->expenses()`

### Category Filtering Pattern

The index action supports an optional `?category=` query parameter:

```php
public function index(Request $request)
{
    $query = $request->user()->expenses()->orderBy('date', 'desc');

    if ($request->filled('category')) {
        $query->where('category', $request->category);
    }

    $expenses = $query->paginate(15)->withQueryString();

    if ($this->isHtmx($request) && $request->has('page')) {
        return view('expenses.partials.table', compact('expenses'));
    }

    return view('expenses.index', [
        'expenses' => $expenses,
        'currentCategory' => $request->category,
    ]);
}
```

The filter bar in the view uses `hx-get` with `?category=X` to reload the table via HTMX, or standard links as fallback.

- **File**: `app/Http/Controllers/ExpenseController.php`
  - **Change**: Replaced `if ($this->isHtmx($request) && $request->has('page'))` with `if ($this->isHtmx($request))`.
  - **Why**: The `&& $request->has('page')` guard meant that HTMX category-filter requests (no `?page=` param) fell through to the full `expenses.index` view. The filter bar uses `hx-target="#expenses-table-container" hx-swap="innerHTML"` — injecting a full page into that div produces broken nested HTML in the DOM. Any HTMX request to `index` (pagination or filter) needs the table partial, not the full page.
  - **How**: Removing the `has('page')` restriction means all HTMX index requests get `expenses.partials.table`. Standard browser requests still receive the full view. The fix aligns the controller with AC13 (dual response: HTMX gets partials, standard gets full page).

- **File**: `resources/views/expenses/partials/table.blade.php`
  - **Change**: Wrapped the table HTML in `@if($expenses->isEmpty())` / `@else` with an `<x-ui.empty-state>` for the empty case.
  - **Why**: When a category filter returns zero results, the controller now returns the table partial (after the fix above). Without this guard, the partial rendered an empty `<tbody>` with no feedback to the user. The sales feature (`table.blade.php` in 4.4) already uses this pattern.
  - **How**: Empty filtered results now show a "No expenses found" empty state instead of a blank table.

- **File**: `tests/Feature/ExpenseControllerTest.php`
  - **Change**: Added `test_htmx_category_filter_returns_partial()` test.
  - **Why**: The original test suite only covered HTMX pagination (`?page=2`). The category-filter HTMX path had no test, which is why the bug above went undetected.
  - **How**: New test sends an HTMX GET to `/app/expenses?category=feed` and asserts `viewIs('expenses.partials.table')`.
