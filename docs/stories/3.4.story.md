### Test Patterns (from existing tests)

Follow the patterns established in `tests/Feature/EggEntryControllerTest.php`:

**Setup pattern:**
```php
use RefreshDatabase;

protected User $user;
protected User $otherUser;

protected function setUp(): void
{
    parent::setUp();
    $this->user = User::factory()->premium()->create();
    $this->otherUser = User::factory()->premium()->create();
}
```

**HTMX test pattern:**
```php
public function test_store_via_htmx_returns_partial(): void
{
    $response = $this->actingAs($this->user)
        ->withHeaders(['HX-Request' => 'true'])
        ->post(route('app.flock.store'), $data);

    $response->assertOk();
    $response->assertViewIs('flock.partials.profile-form');
}
```

**Standard request pattern:**
```php
public function test_store_redirects_on_success(): void
{
    $response = $this->actingAs($this->user)
        ->post(route('app.flock.store'), $data);

    $response->assertRedirect(route('app.flock.index'));
    $response->assertSessionHas('success');
    $this->assertDatabaseHas('flock_profiles', [...]);
}
```

**Cross-user access denial pattern:**
```php
public function test_user_cannot_update_another_users_profile(): void
{
    $profile = FlockProfile::factory()
        ->for($this->otherUser)
        ->create();

    $response = $this->actingAs($this->user)
        ->put(route('app.flock.update', $profile), $data);

    $response->assertForbidden();
}
```

**Free-tier enforcement pattern:**
```php
public function test_free_user_is_blocked(): void
{
    $freeUser = User::factory()->create(); // default tier = free

    $response = $this->actingAs($freeUser)
        ->get(route('app.flock.index'));

    $response->assertRedirect(route('app.dashboard'));
}

public function test_free_user_htmx_gets_premium_gate(): void
{
    $freeUser = User::factory()->create();

    $response = $this->actingAs($freeUser)
        ->withHeaders(['HX-Request' => 'true'])
        ->get(route('app.flock.index'));

    $response->assertOk();
    $response->assertSee('premium'); // or specific gate content
}
```

### current_count Test Strategy (AC: 3)

The `current_count` decrement logic is the most critical piece to test. The unit test (`FlockBatchCurrentCountTest`) tests the model-level increment/decrement operations directly. The feature tests (`DeathRecordControllerTest`) test the full HTTP flow including the count adjustments.

**Key scenarios to cover:**

| Scenario | Initial | Action | Expected |
|----------|---------|--------|----------|
| Create death | current_count=10 | POST death count=3 | current_count=7 |
| Update death (increase) | current_count=7, death.count=3 | PUT count=5 | current_count=5 |
| Update death (decrease) | current_count=5, death.count=5 | PUT count=2 | current_count=8 |
| Delete death | current_count=7, death.count=3 | DELETE | current_count=10 |
| Create death to zero | current_count=3 | POST count=3 | current_count=0 |
| Reject over-count | current_count=5 | POST count=6 | Validation error |

### Nested Resource Scoping Tests (AC: 5)

Cross-batch scoping ensures that a batch event or death record can only be accessed through its parent batch's route. Test scenarios:

```php
// Event belongs to batch 1, try to update via batch 2's route
$batch1 = FlockBatch::factory()->for($this->user)->create();
$batch2 = FlockBatch::factory()->for($this->user)->create();
$event = BatchEvent::factory()->for($batch1)->create(['user_id' => $this->user->id]);

$response = $this->actingAs($this->user)
    ->put(route('app.batches.events.update', [$batch2, $event]), $data);

$response->assertNotFound(); // or 403, depending on implementation
```

This tests both ownership AND parent scoping — the user owns everything, but the route parent doesn't match.

## Testing

### Testing Standards (from Architecture)

- **Framework:** PHPUnit 11.x with Laravel HTTP Tests
- **Trait:** `RefreshDatabase` on all test classes
- **Naming:** `test_` prefix, snake_case, descriptive method names
- **Assertions:** Use Laravel's built-in assertion methods (`assertOk`, `assertForbidden`, `assertRedirect`, `assertDatabaseHas`, `assertSessionHas`, `assertViewIs`, `assertSee`)
- **HTMX testing:** Use `->withHeaders(['HX-Request' => 'true'])` to simulate HTMX requests
- **Factory states:** Use `->premium()`, `->for($user)`, `->create()` pattern
- **No mocks for DB:** Use `RefreshDatabase` with real database (SQLite in-memory or MariaDB via Docker)

### Completion Notes
- **Bug fix: Missing `AuthorizesRequests` trait** — `FlockBatchController`, `BatchEventController`, and `DeathRecordController` all use `$this->authorize()` but the base `Controller` class didn't include the `AuthorizesRequests` trait (Laravel 12 doesn't add it by default). Added the trait to `app/Http/Controllers/Controller.php`.
- **Bug fix: SQLite-incompatible migrations** — `flock_batches` and `death_records` migrations used `ALTER TABLE ... ADD CONSTRAINT CHECK(...)` which SQLite doesn't support. Wrapped with `DB::getDriverName() !== 'sqlite'` guard so tests can run with in-memory SQLite.
- **Adapted Task 1 store tests** — The story assumed a POST `/app/flock` route, but `FlockProfileController` only has `index` (auto-creates profile on GET) and `update`. Tests were adapted to test auto-creation behavior and update validation instead.
