# Story 1.5: Middleware & Policy Foundation

## Status

Ready for Review

## Story

**As a** developer,
**I want** the `EnsurePremiumTier` and `DetectHtmx` middleware and the `HandlesHtmx` trait in place,
**so that** tier gating and HTMX detection work before feature controllers are built.

## Acceptance Criteria

1. `EnsurePremiumTier` middleware: blocks free-tier users from premium routes — returns partial for HTMX, redirect with flash for standard requests
2. `DetectHtmx` middleware: sets `$request->isHtmx()` helper based on `HX-Request` header
3. `HandlesHtmx` trait: provides dual-response helpers for controllers
4. Middleware registered in `bootstrap/app.php`
5. Premium middleware applied to route group in `routes/web.php`
6. Base Policy pattern established (ownership check `$user->id === $model->user_id`)

**Integration Verification:**

- IV1: Free-tier user accessing `/app/expenses` gets redirected with flash message
- IV2: HTMX request to premium route returns `<x-premium-gate>` partial
- IV3: `$request->isHtmx()` correctly detects HTMX vs standard requests

### API Specifications

**Route Architecture** — premium routes are nested inside auth group:
```
Route::middleware(['auth'])->prefix('app')->name('app.')->group(function () {
    // Free-tier routes (dashboard, eggs)
    Route::middleware(['premium'])->group(function () {
        // Premium routes: expenses, flock, batches, customers, sales, etc.
    });
});
```
[Source: architecture/api-specification-routes-htmx.md#route-architecture]

**Premium Middleware Response Contract:**
- HTMX request → return `view('partials.premium-gate', ['feature' => $request->route()->getName()])` (200 status)
- Standard request → `redirect()->route('app.dashboard')->with('warning', 'Upgrade to Premium to access this feature.')`
[Source: architecture/backend-architecture.md#premium-middleware, architecture/core-workflows.md#workflow-5-premium-feature-gate]

### Technical Constraints

- **Middleware registration:** Laravel 12 uses `bootstrap/app.php` for middleware config, not the old `Kernel.php` approach
- `DetectHtmx` should be global middleware (runs on every request) — use `$middleware->append()`
- `EnsurePremiumTier` should be a named alias (`premium`) — use `$middleware->alias()`
- **Ownership scoping (Critical Rule #1):** Every query MUST start from `$request->user()->relationship()` — policies enforce this at the authorization layer
- **Policies for authorization (Critical Rule #8):** Never check ownership in controllers directly
- The `partials.premium-gate` view already exists from Story 1.4 at `resources/views/partials/premium-gate.blade.php`
[Source: architecture/coding-standards.md#critical-rules, architecture/security-and-performance.md#security]

### Testing Standards

- Framework: PHPUnit 11.x (Laravel default)
- Use `RefreshDatabase` trait for clean state per test
- Test method naming: `snake_case` with `test_` prefix
- Run with: `php artisan test --filter=Middleware` or `php artisan test --filter=Policy`

### Testing Patterns

- Use `$this->actingAs($user)` for authenticated requests
- Use `$this->withHeaders(['HX-Request' => 'true'])` for HTMX request simulation
- Assert redirects with `assertRedirect()` and flash with `assertSessionHas()`
- For HTMX responses, assert 200 status and content contains expected markup
- For policy tests, instantiate policy directly and call methods with User + Model instances
- Cross-user access denial is critical — test that user A cannot access user B's records
