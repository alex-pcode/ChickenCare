## Dev Notes

### Project Context

This is the **third and final story in Epic 2** (Egg Tracking — Free Tier). Stories 2.1 (data layer) and 2.2 (controller & views) must both be complete. This story's primary value is **pattern establishment** — the EggEntry test suite becomes the template that developers copy when building tests for Expenses, Feed, Customers, Sales, and all other CRUD features in Epics 3–6.

### Why This Story Exists

The epic description states: *"so that this first feature validates our testing patterns for all subsequent features."* The key deliverable is not just test coverage for egg tracking, but a **proven, copy-paste-ready test pattern** that covers:

1. **Unit tests:** model fillable/casts/relationships/scopes, factory output validation
2. **Feature tests — CRUD:** store/update/delete for both standard and HTMX paths
3. **Feature tests — validation:** required fields, enum constraints, boundary values, both request paths
4. **Feature tests — authorization:** cross-user denial (403) for both standard and HTMX paths
5. **Feature tests — tier access:** free and premium users can access, unauthenticated cannot
6. **Feature tests — UX:** pagination, empty state, edit form partial
7. **Feature tests — error handling:** HTMX 422 on validation failure, HTMX 403 on policy denial


### Validation Rules Reference

| Field | Rules | Boundary Tests |
|-------|-------|----------------|
| `date` | required, date, before_or_equal:today | future date rejected, malformed string rejected |
| `count` | required, integer, min:0 | 0 accepted, -1 rejected, non-integer rejected |
| `size` | nullable, in:small,medium,large,extra-large,jumbo | invalid enum rejected, null accepted |
| `color` | nullable, in:white,brown,blue,green,speckled,cream | invalid enum rejected, null accepted |
| `notes` | nullable, string, max:1000 | null accepted, oversized string rejected |

### HTMX Error Response Contract

Per `error-handling-strategy.md`:

| Scenario | Status | Standard Response | HTMX Response |
|----------|--------|-------------------|---------------|
| Validation failure | 422 | Redirect back with errors | Re-render form with `@error` messages |
| Policy denial | 403 | 403 error page | 403 response |
| CSRF mismatch | 419 | Error page | JS redirect to `/login` |

The HTMX 422 handling relies on the `htmx:beforeSwap` event listener in `app.js` that sets `shouldSwap = true` for 422 responses.

[Source: architecture/error-handling-strategy.md]
