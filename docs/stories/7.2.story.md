# Story 7.2: Dynamic HTML, HTMX, and JSON Cache Headers

## Status

Done

## Story

**As a** ChickenCare user navigating authenticated and HTMX-powered pages,
**I want** dynamic responses to be explicitly non-storable,
**so that** the browser does not replay stale session-bound HTML, fragments, or JSON.

## Acceptance Criteria

1. Authenticated full HTML responses, including boosted HTMX full-page responses, return `Cache-Control: private, no-store`.
2. Authenticated HTMX partials and middleware-generated fragments, including premium-gate and validation responses, return `Cache-Control: private, no-store`.
3. Authenticated JSON endpoints return `Cache-Control: private, no-store`.
4. Guest auth pages return `Cache-Control: private, no-store`.
5. Guest marketing pages are not made `public` or shared-cacheable while they still render through the current CSRF-bearing guest layout.
6. The policy is applied centrally through Laravel middleware rather than duplicated across controllers.
7. No `ETag` or `Last-Modified` behavior is introduced for the covered dynamic responses.
8. Focused feature tests verify representative guest HTML, authenticated HTML, boosted full-page HTML, HTMX partials, premium-gate fragments, validation errors, and JSON endpoints.

## Dev Notes

### Source Findings

- Public routes live in `routes/web.php` and currently include the landing page and costs page, while authenticated application routes live under the `/app` group.
- `routes/auth.php` defines guest login, registration, social-auth, forgot-password, and reset-password flows.
- Both layouts emit a CSRF token meta tag, and `resources/views/layouts/app.blade.php` also enables `hx-boost` on the body and injects HTMX CSRF headers.
- `bootstrap/app.php` registers `DetectHtmx` and custom HTMX-aware exception rendering.
- `app/Providers/AppServiceProvider.php` defines `Request::macro('isHtmx')`.
- Multiple controllers branch on HTMX request shape and return partial HTML for non-boosted HTMX requests, while boosted navigation still returns full HTML.
- `app/Http/Middleware/EnsurePremiumTier.php` can generate HTMX HTML before controller execution.
- Repo search found no explicit app-level `Cache-Control`, `ETag`, or `Last-Modified` policy in `app/`, `routes/`, or `bootstrap/`.
- Existing browser verification showed Laravel already returning `Cache-Control: no-cache, private` for guest HTML, guest auth HTML, authenticated HTML, and boosted authenticated HTML, so this story formalizes a stricter `private, no-store` contract.

### Implementation Notes

- Header ownership for dynamic responses belongs in Laravel middleware, not in Apache.
- Guest marketing pages should stay conservative because the current guest layout still emits `csrf_token()`.
- The middleware should be broad enough to cover controller responses, middleware-generated fragments, and HTMX validation rendering without adding controller-by-controller exceptions.
- Avoid mixing validator-based caching or route-specific public rules into the first implementation.

### Code Quality Assessment

This is a textbook centralized cache-header implementation. `SetDynamicResponseCacheHeaders` is short, single-purpose, and applies the conservative `private, no-store` policy on the response phase — exactly the right shape for a header-stamping middleware. Registration via `prepend` on the web stack means it wraps all other web middleware and gets the final word on `Cache-Control`, including responses produced by `EnsurePremiumTier` before controller execution and by the HTMX validation `renderable` in `bootstrap/app.php`. ETag and Last-Modified are explicitly stripped, so AC7 is enforced by code, not just convention.

The `BinaryFileResponse` / `StreamedResponse` skip is the right defensive carve-out — file downloads and SSE streams have their own header semantics and should not be force-rewritten — and it does not affect any of the eight covered response classes.

### Security Review

No concerns. The conservative blanket policy is the correct posture for a session-bound, CSRF-bearing app — it eliminates back-button replay of authenticated HTML/JSON and keeps guest pages out of shared caches while CSRF tokens are still embedded in the guest layout. No sensitive data is exposed; the change strictly tightens caching.

### Performance Considerations

Negligible per-response cost (one header set, two header removes). No measurable impact expected. The trade-off — losing 304 revalidation on dynamic responses — is the intended behavior, not a regression.
