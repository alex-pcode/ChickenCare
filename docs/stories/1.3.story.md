### App Layout — Exact Markup

```html
{{-- resources/views/layouts/app.blade.php --}}
<!DOCTYPE html>
<html lang="{{ str_replace('_', '-', app()->getLocale()) }}">
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <meta name="csrf-token" content="{{ csrf_token() }}">
    <title>{{ config('app.name') }} — @yield('title', 'Dashboard')</title>
    @vite(['resources/scss/app.scss', 'resources/js/app.js'])
</head>
<body hx-headers='{"X-CSRF-TOKEN": "{{ csrf_token() }}"}'>
    <div class="app-layout">
        <x-layout.sidebar />
        <main class="app-layout__main">
            <x-layout.navbar :title="$__env->yieldContent('title', 'Dashboard')" />
            <x-ui.flash />
            <div class="app-layout__content" id="main-content">
                @yield('content')
            </div>
        </main>
    </div>
    <div id="modal-container" aria-live="polite"></div>
</body>
</html>
```

**Note:** The navbar receives its title via `$__env->yieldContent('title', 'Dashboard')` which reads the `@section('title')` from child views and passes it as a component prop. This bridges the layout `@yield` system with the component `@props` system.

**Implementation note:** Use `@if(auth()->user()->isPremium())` to conditionally show/hide premium items. Do NOT use CSS to hide them — they should not be in the DOM for free-tier users. The `EnsurePremiumTier` middleware (Story 1.5) is the server-side enforcer; the sidebar just controls visibility.

**Active link detection:** Use `request()->routeIs('app.dashboard')` to add `.sidebar__link--active` class and `aria-current="page"` attribute. Use wildcard matching for sections: `request()->routeIs('app.eggs.*')`.

**Unresolved routes:** Routes for premium features don't exist yet (created in later epics). Wrap premium links in `@if(Route::has('route.name'))` checks to avoid errors, or use `#` as a placeholder href. The sidebar must not break if routes are not yet registered.

### Sidebar Responsive Behavior

- **Desktop (>=1024px):** Full sidebar visible, fixed width (~250px)
- **Tablet (768px–1024px):** Sidebar collapsed to icon-only (~60px), expands on hover or toggle
- **Mobile (<768px):** Sidebar hidden off-screen, toggled via hamburger button in navbar, overlays content

Use Alpine.js for toggle state:

```html
<aside class="sidebar" x-data="{ open: false }" :class="{ 'sidebar--open': open }"
       @toggle-sidebar.window="open = !open">
```

Navbar hamburger button dispatches event:

```html
<button class="navbar__toggle" @click="$dispatch('toggle-sidebar')" aria-label="Toggle navigation">
```

### Navbar Component

**Important:** `@yield('title')` does not work inside a Blade component — it is a layout-level directive. The navbar should receive the page title via a prop or `View::share()`. Recommended approach:

- In child views: `@section('title', 'Egg Tracking')` (this still works for the `<title>` tag in the layout)
- Pass title to navbar via a `$title` prop or use `View::shared('pageTitle')` from a view composer
- Simplest approach: accept a `$title` prop with a default: `@props(['title' => 'Dashboard'])`

```html
{{-- resources/views/components/layout/navbar.blade.php --}}
@props(['title' => 'Dashboard'])

<header class="navbar">
    <button class="navbar__toggle" @click="$dispatch('toggle-sidebar')" aria-label="Toggle navigation">
        <!-- hamburger icon SVG -->
    </button>
    <h1 class="navbar__title">{{ $title }}</h1>
    <div class="navbar__user-menu" x-data="{ open: false }">
        <button @click="open = !open" class="navbar__user-button">
            {{ auth()->user()->name }}
        </button>
        <div x-show="open" @click.away="open = false" class="navbar__dropdown">
            <a href="{{ route('app.account.edit') }}" class="navbar__dropdown-item">Account</a>
            <form method="POST" action="{{ route('logout') }}">
                @csrf
                <button type="submit" class="navbar__dropdown-item">Logout</button>
            </form>
        </div>
    </div>
</header>
```

### Coding Standards Reminders

- **SCSS BEM naming:** `.block__element--modifier` — e.g., `.sidebar__link--active`
- **SCSS files:** `_` prefix, kebab-case — e.g., `_variables.scss`
- **Blade components:** dot-namespaced — `<x-layout.sidebar>`
- **Blade views:** kebab-case filenames
- **No Eloquent in Blade:** Pass all data from controllers (sidebar uses `auth()->user()` which is acceptable — it's the authenticated user, not a query)
- **No raw HTML:** Always `{{ }}`, never `{!! !!}` for user content
- **ARIA requirements:** `role="navigation"`, `aria-current="page"`, `aria-label` on nav, `role="alert"` on flash
