# Story 8.3: Offline Read Support via Service Worker Caching

## Status

Ready for Done

## Story

**As a** ChickenCare user with intermittent mobile connectivity,
**I want** recently viewed pages and assets to load when I am offline,
**so that** I can still check yesterday's egg counts, feed status, and flock data near the coop.

## Acceptance Criteria

1. Precaching covers the offline fallback page, the web app manifest, the root favicon, and a small set of critical fonts and icons needed by the existing layouts.
2. Runtime caching for `/build/assets/*` uses a cache-first strategy consistent with the immutable browser-cache policy defined in Story 7.1.
3. Authenticated full-page HTML uses a network-first strategy with a short timeout, then the last cached response for that same URL, then the offline fallback page.
4. HTMX fragment requests identified by the `HX-Request` header use network-first with no offline HTML fallback; failures return a minimal fragment the app can render as an inline offline notice without corrupting the current DOM.
5. Authenticated JSON endpoints are never served from cache; offline requests return a network error so existing callers can handle the failure explicitly.
6. The service worker never caches responses marked with `Cache-Control: private, no-store` beyond the per-URL last-seen copy required for offline HTML fallback, and all cached entries remain origin-scoped so no cross-user leakage path is introduced.
7. An `/offline` Blade view exists and is styled with the existing SCSS tokens so the offline fallback matches the current application visual language.

## Dev Notes

### Source Findings

- Epic 8 defines the PWA layer as a first-party enhancement on top of the existing Laravel, Blade, HTMX, and Alpine stack with service worker scope fixed at `/`.
- Story 8.2 establishes the service worker lifecycle, root-scoped registration, cache versioning, and deploy-time cache cleanup that this story must build on rather than replace.
- Story 7.1 establishes that fingerprinted assets under `/build/assets/*` are immutable and therefore suitable for cache-first runtime handling.
- Story 7.2 establishes that authenticated dynamic HTML, HTMX fragments, and JSON responses are not general browser-cacheable and require careful handling if the service worker keeps last-seen HTML fallback copies.

### Dependencies and Shared Contracts

- Depends directly on Story 8.2 because cache versioning, registration gating, activation cleanup, and update behavior are prerequisites for safe offline-read caching.
- Depends on Epic 7 cache policy decisions, especially Story 7.1 for immutable build assets and Story 7.2 for conservative handling of authenticated dynamic responses.
- Establishes the shared offline-read contract:
  - `/offline` is the terminal full-page fallback
  - `/build/assets/*` stays cache-first and immutable-aware
  - Full-page HTML may use a URL-specific last-seen fallback copy
  - HTMX fragments never receive full offline page HTML as fallback
  - Authenticated JSON is always online-only
- Story 8.4 reuses the HTMX-safe offline notice pattern from this story, but must not blur the line between read fallback and write replay.
- Story 8.6 depends on this story for `/offline` availability, offline navigation verification, and the final PWA audit baseline.

### Implementation Notes

- The offline fallback page should be a controlled first-party page, not the browser's default offline error.
- The first implementation should stay intentionally narrow: a small precache set, explicit route matching, and no attempt to make the whole application offline-first.
- HTMX request detection must be based on request headers because the fallback behavior differs materially from full-page navigation.
- Returning offline page HTML to a fragment target would risk DOM corruption, so the minimal offline fragment should be a separate response shape with predictable markup.

## Testing

- Validate in a built environment with the Story 8.2 service worker active rather than only through the Vite dev server.
- Use browser DevTools offline mode to confirm a previously visited authenticated page loads from the last cached HTML copy.
- Use browser DevTools offline mode to confirm a never-visited authenticated route falls back to `/offline`.
- Exercise at least one HTMX fragment request offline and verify the returned fragment is an inline offline notice, not full-page markup.
- Exercise at least one authenticated JSON request offline and verify it fails with a network error rather than a cached payload.
- Return online, reload a previously visited page, and confirm the network response refreshes the cached HTML for that URL.
