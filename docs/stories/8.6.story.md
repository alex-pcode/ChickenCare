# Story 8.6: PWA Tests and Lighthouse Verification

## Status

Ready for Done

## Story

**As a** developer,
**I want** PWA behavior covered by targeted tests and a Lighthouse baseline,
**so that** regressions in manifest wiring, service worker scope, offline fallback, and offline queue behavior are caught before they ship.

## Acceptance Criteria

1. A PHPUnit feature test verifies the main Blade layouts emit the manifest link, `theme-color`, and `apple-touch-icon` tags for both guest and authenticated responses.
2. A PHPUnit feature test verifies `public/manifest.webmanifest`, `public/sw.js`, and the required PWA icon files exist and are served at their expected public paths; manifest and icon assets carry the Story 7.1 unhashed-media cache policy, while `sw.js` carries the no-cache policy established in Story 8.5.
3. A JS unit test or a documented, repeatable manual DevTools verification script exercises the offline queue module and proves enqueue on offline failure, replay on `online`, dedupe after successful replay, and surfacing of non-retryable errors.
4. A Lighthouse PWA audit is run against a built production environment and recorded in deploy notes; installability passes, the offline start page loads, and no critical PWA audit failures remain.
5. `DEPLOY.md` is updated with a PWA verification checklist covering service worker version bumps on release, manifest availability, and `/offline` route verification on the deployed host.
6. `DEPLOY.md` includes a rollback note describing how to disable the PWA layer quickly by unregistering the service worker script and removing the manifest link, without redeploying the entire Laravel application.

## Dev Notes

### Source Findings

- `resources/views/layouts/app.blade.php` and `resources/views/layouts/guest.blade.php` currently emit CSRF and Vite assets but do not yet show PWA metadata tags, so this story depends on earlier Epic 8 layout work being present before tests can pass.
- `resources/js/app.js` currently bootstraps HTMX, Alpine, and other global client behavior; there is no dedicated JS test harness in the repo yet, so this story must either add a narrow one or document a deterministic manual queue-verification script.
- `tests/Feature/Http/CacheHeadersTest.php` establishes the repo pattern for focused PHPUnit HTTP and header assertions.
- `DEPLOY.md` already documents Apache-owned static cache headers and production asset build and upload flow, but it does not yet contain PWA-specific verification, Lighthouse evidence, or rollback guidance.

### Dependencies and Shared Contracts

- Depends on Story 8.1 for the manifest, icons, and layout metadata.
- Depends on Story 8.2 for service worker registration, `SW_VERSION`, and update behavior.
- Depends on Story 8.3 for the `/offline` route and offline navigation behavior.
- Depends on Story 8.4 for the offline queue module, replay classification, and failure semantics.
- Depends on Story 8.5 for the final Apache and Plesk MIME, cache, and static-serving contract.
- Establishes the shared verification contract for Epic 8 closure:
  - `php artisan test --filter=Pwa` remains the narrow Laravel verification entry point
  - Queue verification evidence must be reproducible, whether automated or scripted manually
  - Lighthouse evidence is part of the epic's deploy-time acceptance, not optional follow-up
  - `DEPLOY.md` becomes the canonical home for release checks and rollback notes

### Implementation Notes

- This is a late-sequence verification story. Do not start implementation until Stories 8.1 through 8.5 are materially complete enough to produce stable manifest, service worker, offline route, and queue behavior.
- Guest and authenticated metadata assertions must cover both layouts because ChickenCare uses separate guest and app Blade layouts.
- Static asset cache headers are owned by Apache and Plesk, not Laravel middleware. Any asset-serving assertion must run against an environment that actually serves static files with those headers.

## Testing

- Run `php artisan test --compact --filter=Pwa` and ensure it covers layout metadata plus public asset-serving assertions.
- Run the offline queue verification suite if a JS harness is added; otherwise execute the documented DevTools or manual script and record the results.
- Run Lighthouse PWA audit against a built production-like environment, not `pnpm run dev`.
- Capture or reference Lighthouse output in `DEPLOY.md` or the agreed evidence location.
- Verify `/offline` responds on the deployed host and that installability remains green after the final build.

**What's missing for AC 2:**
- HTTP response tests using `$this->get('/manifest.webmanifest')` to verify MIME type and cache headers

**Recommendation:** For AC 2 cache-header tests, consider a PHPUnit test that at minimum verifies the files are publicly reachable via HTTP (even without Apache cache headers), and document that cache-header verification requires the production `curl -I` checklist from AC 5.
