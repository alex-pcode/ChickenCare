## Dev Notes

### Project Context

This is Story 3.2 of **Epic 3: Flock & Batch Management**. Batches are the core data entity for premium poultry tracking — each batch represents a group of birds acquired together. The batch detail view introduces a **tab switching pattern** (overview/events/deaths) that will be reused in later features.

**Dependency:** Story 3.1 (Flock Profile & Events) should be completed first, as it establishes the premium route group and flock-related patterns. However, FlockBatch is independent of FlockProfile at the data level — no FK relationship between them.

### Database Schema (from architecture)

**`flock_batches` table:**
```
id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY
user_id         BIGINT UNSIGNED NOT NULL (FK → users.id CASCADE)
batch_name      VARCHAR(255) NOT NULL
breed           VARCHAR(255) NOT NULL
acquisition_date DATE NOT NULL
initial_count   INT UNSIGNED NOT NULL
current_count   INT UNSIGNED NOT NULL DEFAULT 0
hens_count      INT UNSIGNED NOT NULL DEFAULT 0
roosters_count  INT UNSIGNED NOT NULL DEFAULT 0
chicks_count    INT UNSIGNED NOT NULL DEFAULT 0
brooding_count  INT UNSIGNED NOT NULL DEFAULT 0
type            ENUM('hens','roosters','chicks','mixed') NOT NULL
age_at_acquisition ENUM('chick','juvenile','adult') NOT NULL
expected_laying_start_date DATE NULL
actual_laying_start_date   DATE NULL
source          VARCHAR(255) NOT NULL
cost            DECIMAL(10,2) NOT NULL DEFAULT 0.00
```

- Constraints: `initial_count > 0`, `current_count >= 0`
- Indexes: `(user_id)`, `(user_id, is_active)`

### Tab Switching Pattern (HTMX)

The batch detail view uses HTMX tab switching — this pattern is documented in the architecture's **Workflow 4**:

```
1. Full page load: GET /app/batches/5 → renders show.blade.php with overview tab
2. Tab click: GET /app/batches/5?tab=events (HX-Request: true) → returns events-tab partial only
3. HTMX swaps #tab-content, hx-push-url updates browser URL
```

**Implementation in controller:**
```php
public function show(Request $request, FlockBatch $batch)
{
    $this->authorize('view', $batch);
    $tab = $request->query('tab', 'overview');

    if ($this->isHtmx($request) && $request->has('tab')) {
        return view("batches.partials.{$tab}-tab", compact('batch'));
    }

    return view('batches.show', compact('batch', 'tab'));
}
```

**Tab HTML pattern:**
```html
<div role="tablist" class="batches__tabs">
    <button role="tab" aria-selected="{{ $tab === 'overview' ? 'true' : 'false' }}"
        class="batches__tab {{ $tab === 'overview' ? 'batches__tab--active' : '' }}"
        hx-get="{{ route('app.batches.show', $batch) }}?tab=overview"
        hx-target="#tab-content" hx-push-url="true">Overview</button>
    <!-- events, deaths tabs similarly -->
</div>
<div id="tab-content" role="tabpanel">
    @include("batches.partials.{$tab}-tab", ['batch' => $batch])
</div>
```

**Important:** Sanitize the `$tab` value to only allow known tab names (overview, events, deaths) to prevent path traversal in the `view()` call.

### Soft Archive, Not Hard Delete

`destroy()` does NOT delete the batch — it archives by setting `is_active = false`. This preserves historical data (death records, events). The UI labels this as "Archive" not "Delete".

### Active/Archived Filtering

Use query parameter `?filter=active|archived|all`. Default to `active`. The controller applies the appropriate scope:
```php
$query = match ($request->query('filter', 'active')) {
    'archived' => $request->user()->flockBatches()->archived(),
    'all' => $request->user()->flockBatches(),
    default => $request->user()->flockBatches()->active(),
};
```

### current_count Initialization

When creating a batch, `current_count` should default to `initial_count` if not explicitly set by the user. This can be handled in the controller:
```php
$data = $request->validated();
$data['current_count'] = $data['current_count'] ?? $data['initial_count'];
```

Story 3.3 will implement automatic decrement of `current_count` when death records are added.

### Placeholder Tab Partials

Events and deaths tabs are **placeholders** in this story — they show an empty state message. Story 3.3 replaces them with real content. This avoids blocking batch CRUD on event/death implementation while still establishing the tab UI pattern.

### Route Registration

The architecture shows `Route::resource('batches', FlockBatchController::class)` inside the premium group. This replaces the current placeholder route at line 32-34 of `routes/web.php`. The resource route generates all 7 RESTful routes with `app.batches.*` naming.

### Coding Standards Reminders

- **Ownership scoping:** Always `$request->user()->flockBatches()` — never `FlockBatch::find()`
- **Policies for all auth:** `$this->authorize('view', $batch)` in controller, never inline ownership checks
- **Validation in Form Requests only**
- **HTMX dual responses** on all mutating actions
- **BEM SCSS:** `.batches__element--modifier`
- **Models are thin:** scopes for active/archived, relationships, casts only

### Accessibility Requirements

- Tab bar: `role="tablist"`, each tab `role="tab"` with `aria-selected`, content area `role="tabpanel"` with `aria-labelledby`
- Batch cards on index: action buttons (`aria-label="Archive batch: {name}"`)
- Forms: `aria-invalid` + `aria-describedby` on error fields
- Filter buttons: `aria-current="true"` on active filter
- Empty state: `role="status"`
- Archive confirmation: `hx-confirm="Archive this batch? It can be found under Archived filter."`

### Improvements Checklist

- [ ] **BUG: Pagination loses filter state** — `FlockBatchController::index` paginates with `->paginate(15)` but never calls `->appends(['filter' => $filter])`. When a user views "Archived" batches and clicks page 2, the filter drops to default `active`, showing wrong data. **Fix:** `$batches = $query->orderBy('acquisition_date', 'desc')->paginate(15)->appends(['filter' => $filter]);`
- [ ] **BUG: Tab active state not updating on HTMX switch** — When clicking a tab, `hx-target="#tab-content"` swaps only the content area. The tab navigation bar (lines 30-49 of `show.blade.php`) stays unchanged — the previously active tab retains the `batches__tab--active` class and `aria-selected="true"`. Three fix options:
